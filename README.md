# ГСМ Контроль — учёт пробега и топлива автопарка

Веб-приложение (PWA) для учёта пробега и расхода топлива Газелей и других машин парка.
Водители отмечают смены и заправки с телефона, руководитель видит состояние парка, расход, перерасход и отчёты.

**Адрес:** https://gsm-kontrol.imakanovr.workers.dev (старый адрес `spid.imakanovr.workers.dev` перенаправляет сюда).

## Что умеет

**Водитель** (телефон, Android или iPhone; ставится на экран «Домой» как приложение):
- начало и конец смены — пробег на «барабанах» одометра + обязательное фото одометра;
- заправка — вид топлива (бензин / газ / дизель), литры, сумма в ₸, цена за литр считается сама, «до полного бака», фото чека по желанию;
- карточка смены с таймером «На линии 3 ч 12 мин», пробег за сегодня;
- работает без интернета: записи и фото хранятся в телефоне и отправляются сами, когда появится связь;
- проверяет ввод: предупреждает, если пробег меньше прошлого или слишком большой скачок.

**Руководитель** (телефон или компьютер):
- **Парк** — все машины карточками: кто на линии и с какого времени, незакрытые смены, одометр, пробег за день, расход и отклонение от нормы; по нажатию — история расхода машины на графике;
- **Отчёт за месяц** — пробег, затраты, литры по видам топлива, перерасход в ₸; график расхода по машинам с отметкой нормы (одинаковые машины сгруппированы, машины с ГБО — отдельно), затраты по дням, таблица и рейтинг водителей;
- **Замечания** — перерасход, пробег вне смены, уменьшение одометра, скачки пробега, незакрытые смены, подозрительно низкий расход;
- **Журнал** всех записей по дням с фото, исправление и удаление ошибочных записей;
- **Машины** — добавление, кузов, виды топлива, закреплённый водитель;
- **Сотрудники** — руководитель сам добавляет водителей и **других руководителей** (сразу с доступом), подтверждает самостоятельные регистрации с выбором роли, меняет роль, задаёт новый пароль, отправляет данные для входа или приглашение в WhatsApp. Последнего руководителя разжаловать нельзя (защита в базе);
- **Выгрузка в Excel**: «Машины», «Водители», «Заправки», «Смены», «Замечания».

## Как считается расход

Метод «от полного бака до полного»: между двумя заправками до полного бака машина сожгла столько,
сколько залили во второй раз (плюс неполные дозаправки между ними). Расход = литры ÷ км × 100.
Газ и бензин у машин с ГБО считаются раздельно.

**Норма** не задаётся вручную. Для каждой машины и вида топлива это медиана расхода по её истории
(до 12 интервалов за 4 месяца). «Текущий» расход машины — среднее по последним 3 интервалам, и норма для
сравнения берётся *до* них, поэтому свежий перерасход не «подтягивает» норму под себя.
Норма сама подстраивается под сезон. Перерасход — расход выше нормы больше чем на 10%; в «Замечания»
попадает превышение от 25%.

Литры распределяются по водителям пропорционально километрам, которые каждый проехал по своим сменам.

## Дизайн

- Образ «приборной панели»: тёмно-синие «чернила», янтарная стрелка топлива, госномера в стиле
  казахстанских табличек, одометр барабанами. Светлая и тёмная тема (по настройке телефона).
- Шрифты Onest (интерфейс, включая казахские буквы и ₸) и Unbounded (логотип, заголовки) — локально, без интернета.
- Цвета видов топлива проверены валидатором палитры на различимость при дальтонизме; контраст текста — WCAG AA.
- Иконки — Lucide.

## Устройство

- Фронтенд: React + TypeScript + Vite, PWA.
- Хостинг: Cloudflare Workers. Собранное приложение упаковывается в один Worker-скрипт
  ([`scripts/build-worker.mjs`](scripts/build-worker.mjs)), публикация — `npm run deploy`.
- Бэкенд: Supabase — Postgres, вход по телефону и паролю, приватное хранилище фото, права доступа (RLS).
- Схема базы: [`supabase/migrations/`](supabase/migrations/) (выполнять по порядку).
- Логика расчёта: [`src/lib/calc.ts`](src/lib/calc.ts), тесты — [`src/lib/calc.test.ts`](src/lib/calc.test.ts).
- Дизайн-система: [`src/styles.css`](src/styles.css), элементы — [`src/components/`](src/components/).

## Развёртывание

1. **Supabase**: создать проект (бесплатный тариф), выполнить по порядку файлы из `supabase/migrations/` в SQL Editor.
2. В Supabase: **Authentication → Sign In / Providers → User Signups** — выключить **Confirm email**
   (водители входят по номеру телефона; служебный адрес вида `77011234567@<проект>.supabase.co`, писем на него не отправляется).
3. Скопировать `.env.example` в `.env` и вписать `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`
   (Project Settings → API).
4. Опубликовать на Cloudflare: `npm install && npm run deploy`
   (нужны переменные `CLOUDFLARE_API_TOKEN` — токен с шаблоном «Edit Cloudflare Workers» — и `CLOUDFLARE_ACCOUNT_ID`).
5. **Первым** зарегистрироваться руководителю — первый пользователь автоматически получает права руководителя.
   Остальных можно добавить в разделе «Сотрудники» или пригласить ссылкой.
